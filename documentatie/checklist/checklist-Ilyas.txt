Knelpunten en oplossingen
•	Rechten: Een gebruiker mocht zichzelf niet admin kunnen maken. Ik heb rol niet in $fillable gezet en de rol wordt alleen server-side gewijzigd.
•	Toegang: Adminpagina’s zijn beveiligd met middleware (role:admin). Andere gebruikers krijgen een 403.
•	SQL-injectie: Ik gebruik Eloquent, dat achter de schermen PDO prepared statements gebruikt. Ik heb nergens zelf queries in elkaar geplakt.
•	Sessies en misbruik: Na het inloggen vernieuw ik de sessie (session()->regenerate()). Inloggen is beperkt tot 10 pogingen per minuut (throttle). Geblokkeerde gebruikers kunnen niet inloggen.
•	Opzet van het project: Bij het installeren liep ik tegen fouten aan (ontbrekende vendor-map, bootstrap/cache en een beschadigde .env). Ik heb geleerd om foutmeldingen stap voor stap te lezen en te herstellen.
Code waar ik trots op ben
php
public function updateRole(Request $r, User $user)
{
    abort_if($user->id === $r->user()->id, 403, 'Je kunt je eigen rol niet wijzigen.');
    $d = $r->validate(['rol' => ['required', Rule::in(array_keys(User::ROLLEN))]]);
    $user->forceFill($d)->save();

    return back()->with('ok', 'Rol bijgewerkt.');
}
Dit is veilig, want alleen bestaande rollen worden geaccepteerd en een admin kan zichzelf niet buitensluiten. De rollen staan op één plek (User::ROLLEN), dus als er een rol bijkomt, hoef ik dat maar één keer aan te passen. De functie is kort en goed te lezen.
